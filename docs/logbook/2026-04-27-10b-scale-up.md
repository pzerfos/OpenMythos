# 10B Token Scale-Up: 16 GPUs, Preemptable Queue

**Date:** 2026-04-27
**Goal:** Scale training from 1B to 10B tokens using 16 GPUs (2 nodes × 8 H100s), resuming from the 1B-token checkpoint.

---

## Context

The 1B-token PoC (job 34019, completed 2026-04-24) validated the full pipeline:
- Architecture trains correctly (loss 12.66 → 3.37 over 31,225 steps)
- ACT all-reduce fix prevents FSDP deadlock
- Grouped MoE dispatch provides 6.7x speedup
- ClearML is now reachable from compute nodes (firewall opened 2026-04-27)

This run scales to 10B tokens on 16 GPUs using the `preemptable` queue.

---

## Configuration

| Parameter | Value |
|-----------|-------|
| Nodes | 2 × `p*` (H100 80GB) |
| GPUs | 16 total (8/node) |
| Queue | preemptable |
| Resume from | `step_0031000.pt` (~1.02B tokens seen) |
| Target tokens | 10B |
| Total steps | 305,175 (same global batch = 32,768 tok/step) |
| Remaining steps | ~273,950 |
| micro_batch | 1 |
| grad_accum | 1 (reduced from 4 — 16 GPUs fill the global batch in one pass) |
| Global batch | 16 × 1 × 1 × 2048 = 32,768 tokens/step |
| ClearML | `granite-mythos / 1b-10b-tokens` |

The global batch size is unchanged from the 4-GPU run (16 GPUs × grad_accum=1 = 4 GPUs × grad_accum=4), so the LR schedule and step numbering are continuous with the prior checkpoint.

Expected step time: ~0.5–0.8s (vs ~2.1s on 4 GPUs) → ~38–60h for remaining 273K steps, subject to preemptions.

## Multi-Node Changes

Nodes have 8 GPUs each, so 16 GPUs requires 2 nodes. New bsub script `deploy/bluevela/bsub_1b_10b.sh` adds:
- `-n 2 -gpu "num=8/task"` (2 tasks, 8 GPUs each)
- `torchrun --nnodes=2 --nproc_per_node=8 --rdzv_backend=c10d --rdzv_endpoint=${MASTER_ADDR}:29500`
- `MASTER_ADDR` extracted from `$LSB_HOSTS` at job start
